# User-facing output prints mangled generic names

## Summary

Several user-visible surfaces print a generic instantiation by its mangled name
(`array__i32`, `list__string`, `array__IShape2Ptr`) instead of the source spelling
(`array<int>`, `list<string>`, `array<IShape2*>`). With `auto x = new T[n]` now deducing
`array<T>`, the mangled spelling reaches ordinary programs through `typeof`.

## Minimal repro

```cflat
import "array.cb";

extern int main()
{
    array<int> d = new int[2];
    auto p = new int[4];
    printf("%s %s\n", typeof(d), typeof(p));   // array__i32 array__i32
    return 0;
}
```

## Observed vs expected

Observed: `typeof` yields `array__i32` for both the declared and the deduced array.
`Test/test_reflect.cb` pins that spelling today (`typeof_auto_int_array`).

Expected: `array<int>` - the same spelling `DisplayNameOfMangledType` already produces for
diagnostics that go through it.

## Where the mangled name leaks

- `typeof(expr)` - `MainListener_PostfixExpression.cpp`, the `CreateGlobalString("typeof", ...)`
  sites: the name is `TypeAndValue.TypeName` verbatim (or `LLVMTypeToTypeName` for `auto`).
- Diagnostics that format `TypeName` directly instead of through `DisplayNameOfMangledType`, e.g.
  "cannot initialize value of type 'array__i32' with a pointer of type 'array__i32*'"
  (decl-init pointer/value mismatch).
- Overload-failure candidate lists print the LLVM function symbol
  (`_set_void_array__IShape2Ptri32IShape2_(...)`) on the candidate lines, while the argument
  lines already show `array<IShape2>`.

## Proposed change

- `typeof`: run the resolved name through `DisplayNameOfMangledType` before interning the
  string; pointer suffix appended after. Update the `test_reflect.cb` expectations to the
  source spelling (`array<int>`, `array<double>`).
- Diagnostics: audit `std::format(... TypeName ...)` sites in `MainListener_*.cpp` and
  `LLVMBackend_*.cpp` for a mangled `TypeName` and route them through
  `DisplayNameOfMangledType` (it reports `writable=false` when the name cannot be rebuilt, in
  which case the mangled form stays).
- Overload candidate lines: print the candidate through the same display path used for the
  argument lines (`ComputeMangledName` has the parameter `TypeAndValue`s; render those, not
  the symbol).

## Alternatives

- Store a display name beside the mangled `TypeName` on `StructData` at instantiation time
  (`mangledTypeDisplayNames` already exists for the non-generic case) and read it everywhere.
  Larger, and it needs the `--init` cache round-trip in the same change.
- Leave `typeof` mangled as a stable reflection key and fix only diagnostics. Rejected by the
  repro: `typeof` is the surface that regular programs print.

## Acceptance

- The repro prints `array<int> array<int>`.
- `test_reflect.cb` `typeof_*` legs use source spellings; no other test asserts a `__` name.
- The three diagnostics named above show `array<int>` / `array<IShape2>` forms.
- No `cflat/locales/` edits by hand; catalog regenerated by the documented pipeline.

Needs a maintainer ruling on whether `typeof` of a generic instantiation should print the
canonical primitive names (`array<i32>`) or the user's spelling (`array<int>`).
