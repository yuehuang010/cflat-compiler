# Implicit pointer -> integer conversion is accepted at initializers and stores

CFlat pointers are not numbers: `doc/LANGUAGE.md` "Integer <-> pointer casts" says every
integer<->pointer move except the literal `0` -> pointer needs an explicit cast. The
integer -> pointer direction is enforced everywhere (`IsImplicitPrimitiveToPointer` /
`RejectImplicitPrimitiveToPointer`), and pointer -> integer is rejected at call arguments and
returns - but pointer -> integer compiles silently at every store position. Maintainer ruling
2026-09-26: an oversight, an explicit cast is required.

Correction: a C++ `int` call parameter does NOT reject an `int*` argument - it fails module
verification instead; see `cpp-pointer-argument-into-int-parameter-fails-verification.md`.

This is what let `internal/issue/p2/cpp-scalar-rvalue-reference-return-reads-address.md` produce a
stack address as a `long` with no diagnostic: the `long&&` C++ return maps to `long*`, and
`long n = s.take();` took the pointer as a number.

## Repro (master cfdbeca4, `--check`; files in scratch/refbug/p2i_*.cb)

```cflat
struct S { long f = 0; };
long takel(long a) { return a; }
extern int main()
{
    long v = 5; long* p = &v;
    long x = p;               // ACCEPTED - should be an error
    x = p;                    // ACCEPTED
    S s = default; s.f = p;   // ACCEPTED
    S t = {f = p};            // ACCEPTED
    long[2] a = default; a[0] = p;  // ACCEPTED
    x += p;                   // ACCEPTED
    takel(p);                 // rejected: no overload matches
    long y = (long)p;         // OK - the explicit cast
    return 0;
}
// long retl() { long* q = &gv; return q; }  -> rejected: cannot return 'long*' from 'long'
// long* p = 7;                              -> rejected with the primitive-to-pointer diagnostic
```

## Fix direction

Add the mirror predicate next to `IsImplicitPrimitiveToPointer`
(`cflat/LLVMBackend_CodegenHelpers.cpp` ~1568): destination is an integer (or other primitive,
enum, bool) and the source is a pointer / array view / function pointer. Add a diagnostic in the
same style ("a pointer is not a number; use an explicit cast '(long)p' to assert this
conversion"), and call it at the same sites as `RejectImplicitPrimitiveToPointer`
(`MainListener_Declarations.cpp` ~6372, `MainListener_Statements.cpp` ~1291,
`MainListener_Expressions.cpp` ~3872 / 12850 / 13245 / 14224 / 14927) plus compound assignment.
Exempt `bool` everywhere (RULED 2026-09-26: bool is special - pointer -> bool is the clean
null / non-null test, so `bool b = p;`, `b = p;`, `if (p)` and friends stay legal). The gate covers
every OTHER integer / enum / char / floating destination.
Expect fallout in core `.cb` libraries and tests that relied on the silent conversion; fix each
with an explicit cast, never by weakening the gate. Negative test:
`Test/errors/err_implicit_pointer_to_integer.cb` covering every position above.
